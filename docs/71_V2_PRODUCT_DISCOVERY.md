## 2. V2 平台定位与已确认范围

**POST V2：类似 GitHub 的科研项目托管与版本化协作平台，连结研究项目、成果与贡献者。**

D19 已确认面向通用科研，首批重点完善材料科学模板与案例。材料领域案例用于验证完整协作流程，不限制其他科研领域建立项目、使用通用模板或配置项目补充字段。

D14 已确认项目以研究问题、实验、资料、结论与证据为主要入口；代码与档案关联到它们。科研内容的建立、修改、提交与评审由使用者主动完成。

D15 已确认编辑采逐步完善：先记录并保存草稿，随研究进展补充条件、方法、资料与证据；送审与发布分别按相应门槛检查完整性。保存草稿不等于形成已被团队接受或已公开的科研结果。

D16 已确认新建项目默认 Public，同时可明确选 Private；沿用公开项目的可发现、可协作方向。D17 另行确认公开项目的新附件默认可下载、可设 Restricted。项目／分支可见性、Blob 存取与使用权仍是分开的设定，不把新的下载默认套用到既有受限附件或解读为任意重用的授权。

D18 已确认默认模板与项目自定义补充字段并存；以统一的科研身份、版本与证据规则保持跨项目可追溯性。

D06／R2 已确认通用预览与基础作图／统计／曲线拟合均属于 V2。D04 的边界仍是实验与外部计算任务在现有工具执行；本次另行加入平台内由用户主动操作的数据分析。分析结果须明确保存并保留原始数据版本、处理与方法参数，不默认生成科研结论或 Evidence Assertion。

Supervisor 前一题把 AI 自动整理放到核心流程，是未经 Owner 要求而引入的产品假设，现已撤回。使用者上传资料后的核心行为是保存、版本管理、授权存取与协作；不默认平台主动替使用者建立科研结论、解读 Evidence 或生成研究记录。日常使用指透过项目、Issues、记录与版本进行工作，不把 POST 定义成自主研究或强制 AI 处理工作台。

建议的主故事：

1. 使用者建立个人／组织科研项目，主动填写研究说明并提交内容。
2. 研究者主动整理代码、资料、实验／计算记录、结论及证据关联，透过 branch／commit 保留版本。
3. 合作者透过 Issues／Discussion／PR 讨论、提出变更、review、处理冲突、合并，并由有权者发布 Release／Asset。
4. 其他使用者发现公开项目、引用／Fork／重用成果、提交外部贡献，保留来源、版本、权利与个人贡献历史。

这个主故事承接原始 POST 愿景与 D13。项目的主要呈现内容、研究记录深度、资料格式、权限与网络互动仍需逐项确认；AI 能力不作核心平台设计的默认前提。

## 3. 已选范围、保留原则与候选范围

### 已选方向

- 以科研项目托管、版本化、协作与公开成果网络为核心；由使用者主动建立研究计画、记录、科研对象、结果档案与来源。
- 科研内容采逐步完善的草稿流程；在送审／发布等正式动作前检查所需信息，不把完整模板前置为首次记录的负担。
- 第一个团队可从网页建立项目、邀请合作、评审、合并、Release 与发布。
- 逐步建立跨项目重用、外部验证／贡献与个人贡献历史。
- 保留现有研究工具，POST 记录其执行与结果；完整 Web 操作核心流程不依赖 CLI Agent。

### 目前仍保留的领域／架构原则

- main 接受状态与 branch 研究中状态分开；Merge 与 Publish 分开。
- 历史 append-only、Release／Asset Version 不可变、citation 不等于 Evidence 或 Dependency。
- 科学冲突由人负责，Agent 不自动决定科学真伪或扩大可见性。
- PostgreSQL／Git／Blob 的真相分工、Next UI／Go API 边界、Files 只读。
- 真实身份的历史贡献不随离职消失；不产生单一科研／真值总分。

上述原则没有被「V2」一词自动取消。若后续产品需求确实改变它们，要明确记录裁定并更新相应规格／ADR。

### 尚未确认为 V2 承诺

- 材料生成模型、模拟排程、HPC／仪器／自动实验室整合。
- 全网文献搜寻、外部资料库自动撷取、论文抽取的供应商与资料权利。
- AI 自动整理／生成科研内容、真实模型／向量服务、AI 外发资料政策、MCP 或外部 Agent 工具面的交付深度；全部不是核心前置要求，Owner 没有接受上一题的 A/B/C 选项。
- 多组织机密 compartment、embargo、联合发布／复杂签核、保密证明公开发现。
- 完整 ELN／LIMS 功能、法规电子签章、样品库存／设备排程、行动原生 App。
- 任意 Git／档案在线编辑、大型社交动态、支付／赏金市场、联邦节点。
